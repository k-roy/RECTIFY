## 3. In-flight: BAM-provenance feature

Decided in chat 2026-05-18:

- **Match policy**: strict equality on `(rectify_git_sha, aligner_name,
  aligner_version)`. No semver tolerance, no per-field overrides at v1.
- **No-sidecar policy**: strict-refuse + `--trust-existing-bams` flag
  (ship now) + retroactive sidecar audit tool (deferred to its own
  workstream).

### 4.2 Layout mismatch — this matters

`rectify run-all`'s `_collect_per_aligner_bams`
(`rectify/core/commands/run/helpers.py:49`) expects per-aligner BAMs at:

```
<sample_output_dir>/<sample_id>.<aligner>.bam
```

Sherlock's actual production layout is:

```
.../set2_cpa_machinery/<sample>/chunks/merged_bams/<sample>_trimmed.<aligner>.bam
```

So one of the following must happen before the dry-run command is even
constructable, let alone runnable:

- **Option A — symlink shim**: for each ready sample, create
  `<sample>/<sample>.{aligner}.bam` symlinks pointing at
  `chunks/merged_bams/<sample>_trimmed.{aligner}.bam`. Lightweight.
  Sidecars (when written) live next to the symlinks.
- **Option B — patch run-all**: teach `_collect_per_aligner_bams` to
  also look at `chunks/merged_bams/<sample>_trimmed.<aligner>.bam`
  with a `--legacy-layout` flag. Heavier but no symlinks to maintain.
- **Option C — full path manifest**: extend manifest schema to allow
  explicit per-aligner BAM paths per sample, bypassing layout
  conventions entirely. Most general but biggest change.

Recommendation for the prelim: **Option A** (symlinks) — minimal blast
radius, no code change, reversible. Document in handoff #2's resume
that future sessions may want B or C.

### 5.4 The `rectify run-all` invocation

```bash
rectify run-all \
  --manifest manifest.tsv \
  --short-read \
  --dT-primed-cDNA \
  --genome /u/project/guillom/shared/references/saccharomyces_cerevisiae/R64-5-1_20240529/S288C_reference_sequence_R64-5-1_20240529.fasta \
  --annotation /u/project/guillom/shared/references/saccharomyces_cerevisiae/R64-5-1_20240529/saccharomyces_cerevisiae_R64-5-1_20240529.gff \
  -o /u/project/guillom/shared/processed/han_2023_ysh1aa_vs_wt_rectify_v0.9.0/results/ \
  --reference WT \
  --threads 16
```

Notes:

- `--short-read --dT-primed-cDNA` is the "oligo-dT short read mode"
  the user referenced. `stages.py:80` shows `--short-read` defaults
  base aligners to `bbmap + bwa` and disables uLTRA/deSALT junction
  aligners by default. `--dT-primed-cDNA` enables AG-mispriming filter
  + poly(A)-tail handling for dT-primed cDNA.
- `--reference WT` makes WT the DESeq2 reference condition for the
  Ysh1AA-vs-WT contrast.
- No `--chunked-alignment`: 4 samples × ~6M reads × short-read =
  bbmap finishes per-sample in well under an hour; inline alignment
  is fine.

### 5.6 Why this needs the provenance feature even though there are
no BAMs to reuse

For consistency. The H2 run will write per-aligner sidecars (one per
sample × per aligner — so 4 × {bbmap, bwa} = 8 sidecars) plus 4
`rectified.bam.prov.json`. Those sidecars are the audit trail the user
asked for. Without provenance shipped, the H2 deposit looks like every
prior deposit — no way to verify which rectify version it came from
once the on-disk BAMs leave the originating session.
